
GUITAR STRING DETECTION ALGORITHM OUTLINE


PURPOSE
-------
Detect which guitar string is producing a note when the same pitch can be 
played on multiple strings. For example, A4 (110 Hz) can be played on both 
the low E string (5th fret) and the open A string - this algorithm 
distinguishes between them.

ASSUMPTION: A separate pitch detection algorithm already provides the 
fundamental frequency (f0) reliably. This algorithm uses that data as input.



SECTION 1: CORE CONCEPT - WHY STRINGS SOUND DIFFERENT


The same note played on different strings has the same fundamental frequency 
but differs in TIMBRE. Timbre is determined by:

1. HARMONIC OVERTONE STRUCTURE
   - When a string vibrates, it produces not just the fundamental frequency 
     but also integer multiples (harmonics): f0, 2×f0, 3×f0, 4×f0, etc.
   - Different strings produce different relative amplitudes of these harmonics
   - Thicker/wound strings emphasize lower harmonics
   - Thinner/unwound strings have stronger higher harmonics (brighter sound)

2. INHARMONICITY
   - Real strings are not perfectly flexible; they have stiffness
   - This causes harmonics to be slightly SHARP compared to perfect multiples
   - The deviation increases with higher harmonic numbers
   - Different strings have different inharmonicity profiles based on:
     * String diameter (thicker = more inharmonicity)
     * String construction (wound vs unwound)
     * Vibrating length (fretted position)
     * String tension

3. SPECTRAL CHARACTERISTICS
   - Spectral centroid (center of mass of frequency content) differs
   - Wound strings have lower spectral centroid (darker sound)
   - Unwound strings have higher spectral centroid (brighter sound)



SECTION 2: THE INHARMONICITY MODEL


This is the most reliable distinguishing feature for string detection.

THEORETICAL BASIS:
- Ideal string harmonic frequencies: f_n = n × f0
- Real string harmonic frequencies: f_n = n × f0 × sqrt(1 + B × n²)

Where B is the INHARMONICITY COEFFICIENT, determined by:
- String core diameter (d)
- String length (L)  
- String tension (T)
- Young's modulus of the string material (E)

KEY INSIGHT:
- Each string has a characteristic B value
- B increases with string thickness
- B decreases with longer vibrating length (lower fret numbers)
- By measuring how much the harmonics deviate from perfect multiples, 
  we can estimate B and match it to known string profiles

PRACTICAL MEASUREMENT:
- Detect peaks in the frequency spectrum at approximate harmonic locations
- Measure the exact frequency of each harmonic peak
- Calculate the deviation from the ideal (n × f0)
- Fit the deviations to the inharmonicity formula to estimate B



SECTION 3: FEATURES TO EXTRACT


A. INHARMONICITY FEATURES (Primary)
   - Deviation of each harmonic (2nd through 10th) from ideal frequency
   - Measured in cents (1 cent = 1/100th of a semitone)
   - Inharmonicity coefficient B (fitted from deviations)
   - Pattern of deviations across harmonics

B. HARMONIC AMPLITUDE FEATURES
   - Relative amplitude of harmonics 1-10 (normalized to fundamental)
   - Ratio of odd to even harmonics
   - Decay rate of harmonic amplitudes
   - Which harmonics are present vs absent

C. SPECTRAL SHAPE FEATURES
   - Spectral centroid: weighted mean of frequencies (indicates brightness)
   - Spectral rolloff: frequency below which 85-95% of energy exists
   - Spectral spread/bandwidth: variance around the centroid
   - Spectral flatness: ratio of geometric to arithmetic mean (tonality)

D. TEMPORAL FEATURES (Optional, from attack portion)
   - Attack time (time to reach peak amplitude)
   - Amplitude envelope shape in first 50-100ms
   - Transient characteristics



SECTION 4: ALGORITHM PIPELINE


STAGE 1: AUDIO INPUT AND PREPROCESSING
----------------------------------------
- Receive audio input in real-time (recommended: 44.1kHz sample rate)
- Buffer audio into frames (recommended: 2048-4096 samples per frame)
- Apply windowing function (Hann or Hamming) to reduce spectral leakage
- Implement onset detection to identify when a new note begins
- Focus analysis on the sustained portion of the note (after attack transient)

STAGE 2: RECEIVE PITCH DATA
----------------------------------------
- Input: fundamental frequency (f0) from external pitch detector
- Input: confidence score from pitch detector
- Convert f0 to MIDI note number for string/fret mapping
- Only proceed if pitch confidence is above threshold

STAGE 3: CANDIDATE STRING FILTERING
----------------------------------------
- Standard guitar tuning (low to high): E2, A2, D3, G3, B3, E4
- For each string, calculate the range of playable notes (open to fret 24)
- Given the detected pitch, determine which strings CAN produce this note
- Example: A4 (110 Hz) can only come from strings 1 (E), 2 (A), or 3 (D)
- This reduces the classification problem significantly

STRING RANGES (Standard Tuning, 24 frets):
- String 6 (Low E): E2 (82.4 Hz) to E4 (329.6 Hz)
- String 5 (A): A2 (110 Hz) to A4 (440 Hz)
- String 4 (D): D3 (146.8 Hz) to D5 (587.3 Hz)
- String 3 (G): G3 (196 Hz) to G5 (784 Hz)
- String 2 (B): B3 (246.9 Hz) to B5 (987.8 Hz)
- String 1 (High E): E4 (329.6 Hz) to E6 (1318.5 Hz)

STAGE 4: FREQUENCY ANALYSIS (FFT)
----------------------------------------
- Compute FFT of the windowed audio frame
- Calculate magnitude spectrum
- Use sufficient FFT size for frequency resolution (at least 4096 points)
- Frequency resolution = sample_rate / FFT_size
- For 44.1kHz and 4096 points: ~10.7 Hz resolution

STAGE 5: HARMONIC PEAK DETECTION
----------------------------------------
- For each expected harmonic (n × f0), search for peaks in a window around it
- Window size should account for inharmonicity (harmonics will be sharp)
- Suggested search range: n × f0 × (1 ± 0.02) for harmonics up to n=10
- Use parabolic interpolation for sub-bin frequency accuracy
- Record: actual frequency, amplitude, and deviation from ideal
- Detect harmonics 1 through at least 10 (more if signal quality allows)

STAGE 6: FEATURE CALCULATION
----------------------------------------
- Calculate inharmonicity coefficient B using least-squares fitting
- Compute spectral centroid from the magnitude spectrum
- Compute spectral rolloff, spread, and flatness
- Normalize harmonic amplitudes relative to fundamental
- Assemble feature vector

STAGE 7: CLASSIFICATION
----------------------------------------
Option A - Template Matching (Simpler):
- Pre-record reference profiles for each string at various fret positions
- Compare extracted features to stored templates
- Use distance metric (Euclidean distance or cosine similarity)
- Select string with closest match

Option B - Rule-Based with Inharmonicity (Recommended starting point):
- Calculate expected B coefficient for each candidate string/fret combination
- Compare measured B to expected values
- Apply thresholds and confidence scoring
- Use spectral features as secondary confirmation

Option C - Machine Learning (Most accurate, requires training data):
- Train classifier (SVM, Random Forest, or Neural Network) on labeled data
- Input: feature vector
- Output: string number with probability scores
- Requires substantial training data from the target guitar

STAGE 8: OUTPUT
----------------------------------------
- String number (1-6, where 1 is high E and 6 is low E)
- Fret number (0-24, where 0 is open string)
- Confidence score (0-1)
- Optionally: second-best guess with confidence



SECTION 5: CALIBRATION PROCESS


The algorithm requires calibration for each specific guitar because:
- String gauge varies between guitar setups
- Pickup position affects harmonic content
- Guitar construction affects resonance

CALIBRATION DATA COLLECTION:
1. Record each string played open
2. Record each string at frets 5, 7, 12 (common overlap points)
3. For each recording, extract and store the feature profile
4. Build lookup tables or train classifier with this data

CALIBRATION STORAGE:
- Store expected inharmonicity coefficient B for each string
- Store typical spectral centroid ranges for each string
- Store harmonic amplitude profiles for each string
- Allow for tolerance ranges



SECTION 6: IMPLEMENTATION CONSIDERATIONS


REAL-TIME PERFORMANCE:
- Target latency: under 50ms for responsive feedback
- FFT computation is the most expensive operation
- Consider using Web Audio API's built-in AnalyserNode for efficiency
- Process frames in a worker thread if needed

BUFFER AND WINDOW SIZING:
- Larger buffers = better frequency resolution but more latency
- Smaller buffers = faster response but less accurate
- Recommended compromise: 2048-4096 samples at 44.1kHz
- Overlap frames by 50-75% for temporal smoothness

FREQUENCY RESOLUTION REQUIREMENTS:
- Need to detect small deviations in harmonic frequencies
- For inharmonicity detection, need resolution better than ~5 Hz
- This requires FFT size of at least 8192 for high accuracy
- Use zero-padding to improve interpolation

HANDLING EDGE CASES:
- Low confidence from pitch detector: skip or flag as uncertain
- Notes that can only come from one string: return immediately
- Very high or very low notes: fewer candidate strings
- Rapid note changes: ensure onset detection resets analysis

NOISE HANDLING:
- Apply noise floor threshold when detecting harmonic peaks
- Ignore peaks below a minimum amplitude
- Consider using median filtering on feature values over time



SECTION 7: DATA STRUCTURES (Conceptual)


PITCH INPUT:
- Fundamental frequency (Hz)
- MIDI note number
- Confidence (0-1)

HARMONIC PEAK DATA (for each detected harmonic):
- Harmonic number (1, 2, 3, ...)
- Expected frequency (n × f0)
- Actual measured frequency
- Amplitude (magnitude)
- Deviation in cents from ideal

EXTRACTED FEATURES:
- Inharmonicity coefficient B
- Array of harmonic amplitudes (normalized)
- Spectral centroid (Hz)
- Spectral rolloff (Hz)
- Spectral spread (Hz)
- Spectral flatness (0-1)

STRING PROFILE (for calibration/template storage):
- String number
- Typical B coefficient range
- Typical spectral centroid range
- Reference harmonic amplitude pattern

DETECTION RESULT:
- String number (1-6)
- Fret number (0-24)
- Confidence score (0-1)



SECTION 8: TESTING AND VALIDATION


TEST CASES TO IMPLEMENT:
1. Single notes on each string at open position
2. Single notes at common fret positions (5, 7, 12)
3. Notes that can only be played on one string (boundary cases)
4. Notes that can be played on 2, 3, or 4 strings (overlap cases)
5. Rapid string changes
6. Notes with varying dynamics (soft vs loud)

ACCURACY METRICS:
- Overall string detection accuracy (%)
- Confusion matrix showing which strings get confused
- Per-string accuracy breakdown
- Confidence score correlation with actual accuracy

EXPECTED PERFORMANCE:
- Research indicates 88%+ accuracy is achievable for isolated notes
- Accuracy typically lower for:
  * Adjacent strings (similar timbres)
  * Higher fret positions (shorter vibrating length reduces differences)
  * Worn or dead strings
